## 1. 业务背景与产品定位

### 1.1 业务背景与痛点分析
随着公司各业务线（智能研发、算法工程、产研办公、客户支持、自动化工作流等）对大语言模型（LLM）能力的依赖加深，各部门在模型资源采购与调用中出现以下典型痛点：
1. **供应商分散与重复采买**：各团队自行采购 OpenAI、Anthropic、DeepSeek、阿里云百炼等上游服务，API Key 分散在数十台服务器与本地开发环境，无法实现采购量级折扣，存在资金浪费与预算失控风险。
2. **凭据安全与泄露隐患**：上游 Master Key 散落在业务代码、配置文件和个人电脑中，一旦泄露难以追溯具体泄露源头，且无法做细粒度的白名单或权限吊销。
3. **接口规范不统一与迁移成本高**：不同厂商接口标准各异（OpenAI、Anthropic Claude Messages API、阿里云原生 SDK 等），业务方模型切换或做跨厂商 A/B 测试时，需要重复修改业务代码。
4. **单点故障与可用性无保障**：上游供应商频繁出现全球网络抖动、海外云服务中断（Cloudflare 502/504）、并发配额触顶（429 Too Many Requests），导致内部关键业务中断，缺乏跨供应商的主备容灾（Failover）与智能重试机制。
5. **用量黑盒与算力归属混乱**：无法精准统计各部门、项目组及个人的 Token 消耗、调用频次与请求成本，无法执行精细化财务核算与分摊。

### 1.2 产品定位与核心目标
**LLM API Gateway** 定位为**公司内部基础设施级统一大模型中转平台（对标并私有化复刻 OpenRouter 核心架构）**。
- **对上（汇集资源）**：统一聚合海内外主流公有云供应商（OpenAI、Anthropic、DeepSeek、阿里云百炼/通义千问、Kimi 等）与内网私有部署模型（vLLM、Ollama、TGI），集中纳管上游凭据与配额池。
- **对下（分发赋能）**：向内部注册用户与业务系统分发标准化内部 API Key，提供**100% 兼容 OpenAI 格式**的标准 HTTP/SSE 接口；提供模型别名、多通道负载均衡、故障自动降级、分级配额控制与实时审计大盘。
- **系统核心原则**：
  - **极简接入**：业务方仅需修改 `BaseURL` 与 `API Key`，零代码改造无缝切换。
  - **高并发与低延迟**：专为公司千人级工程研发与业务场景设计，核心网关附加延迟不超过 15ms，支持 500~1000 QPS 高并发。
  - **高可用与确定性**：实现毫秒级健康探测与跨厂商自动故障转移（Fallback），屏蔽上游异常。

### 2.2 核心业务使用场景与时序

#### 场景 1：内部研发人员自助接入大模型应用（日常开发）
1. 开发者通过公司内部统一 SSO（飞书/钉钉/OAuth2）单点登录网关自助门户 `/portal`。
2. 开发者在“我的 API Key”页面创建用于个人开发测试的 Key（例如设置名称为 `Cursor-Local-Dev`，绑定默认额度 $50/月）。
3. 平台生成专属 Key：`sk-corp-xxxxxxxxx`（仅在创建成功时明文展示一次）。
4. 开发者在本地 IDE、Cursor、LangChain 或业务配置文件中配置：
   - `OPENAI_API_BASE=https://llm-gateway.corp.internal/v1`
   - `OPENAI_API_KEY=sk-corp-xxxxxxxxx`
5. 发起请求，网关校验身份与额度后，按配置的模型别名路由至对应的上游厂商，请求全链路正常打通。

#### 场景 2：生产级高并发业务请求与跨供应商自动 Fallback（高可用容灾）
1. 线上客服 Agent 以 300 QPS 持续调用 `gpt-4o` 模型。
2. 上游 OpenAI 官方集群突然发生抖动，连续 3 次返回 `HTTP 502/504` 或超时。
3. 网关断路器（Circuit Breaker）触发熔断判定，标记 OpenAI 主通道不可用。
4. 网关依据预设的路由降级链条（Fallback Chain），在 50ms 内无感重试并切换至备份渠道（如 Azure OpenAI 的 `gpt-4o` 部署节点，或自动回退至同级别的 `claude-3-5-sonnet`）。
5. 业务方客户端正常收到流式 SSE 响应，调用方无感知报错，确保公司核心业务 0 中断。

#### 场景 3：部门预算硬隔离与超额熔断控制（成本合规）
1. 部门 A 本月设定预算额度上限为 50,000,000 Tokens（或对应等值 $500）。
2. 当月消耗达 80% 时，系统通过企业 Webhook（飞书机器人/邮件）向部门管理员发送告警。
3. 当月消耗达 100% 且未申请扩容时，该部门下所有普通成员发起的 API 请求触发配额熔断，网关直接返回 `HTTP 429 Insufficient Quota`，阻断外部上游计费，同时超级管理员可在后台为特定应急业务一键追加白名单或提额。

| `POST` | `/v1/chat/completions` | 核心聊天交互接口（支持非流式 JSON 与 SSE 流式） | Bearer Token (`sk-corp-*`) | 核心兼容，支持自定义路由参数与回退链 |
| `POST` | `/v1/completions` | 文本补全传统接口（兼容旧版客户端与 Copilot） | Bearer Token (`sk-corp-*`) | 协议兼容 |
| `POST` | `/v1/embeddings` | 向量化嵌入接口（用于 RAG 与知识库向量计算） | Bearer Token (`sk-corp-*`) | 协议兼容 |

### 4.2 异构协议转接矩阵（Protocol Adapters）
网关引擎层需实现插件化适配器（Adapter Pattern），在内存中实现高效解析转换：

| 客户端入参协议 | 目标上游供应商 | 请求体转换策略 | 响应体转换策略 | 特殊处理与约束 |
| :--- | :--- | :--- | :--- | :--- |
| **OpenAI 兼容** | **OpenAI / Azure** | 直通转发（Pass-through），仅替换 `Authorization` 头为供应商 Key。 | 直通转发，网关旁路异步抓取 `usage` 数据。 | 处理 Azure 部署名与 `api-version` Query 参数映射。 |
| **OpenAI 兼容** | **Anthropic Claude** | 将 `messages` 拆分为 `system` 字符串与角色数组；转换 `tools` / `tool_choice` 为 Claude 规范。 | 将 `content_block_delta` 映射为 OpenAI `choices[0].delta`；包装最终 `usage`。 | 映射 Anthropic Cache Control 头部；处理最大 Token 数限制转换。 |
| **OpenAI 兼容** | **DeepSeek (官方/百炼)** | 官方原生兼容 OpenAI 格式；直接补齐 Reasoning Token 相关字段映射。 | 透传 `reasoning_content` 字段至 OpenAI 扩展字段，确保 DeepSeek-R1 思考链完整呈现。 | 确保思考链内容在 SSE 增量输出时不被丢弃。 |
| **OpenAI 兼容** | **阿里百炼 / 通义千问** | 若调用兼容端点直接转发；若调用原生 DashScope，则转换 Payload 结构。 | 统一标准化为 OpenAI choices 结构。 | 兼容 DashScope 异步输出格式（如需）。 |
| **OpenAI 兼容** | **私有部署 (vLLM / Ollama)** | 直通转发至内网专用集群反向代理，添加内网服务鉴权 Token。 | 直通转发，监控 GPU 吞吐指标。 | 自动处理内网 HTTP Keep-Alive 与长连接保持。 |

### 4.3 SSE（Server-Sent Events）流式管道规范
对于高并发 LLM 网关，流式调用的开销主要集中在**连接持有数与内存缓冲区**。具体规范如下：
1. **协议规范**：
   - 响应头必须声明：
     ```http
     Content-Type: text/event-stream; charset=utf-8
     Cache-Control: no-cache, no-transform
     Connection: keep-alive
     X-Accel-Buffering: no
     ```
   - 每条消息必须以 `data: {...}\n\n` 格式输出，结束标志必须为标准的 `data: [DONE]\n\n`。
2. **零拷贝转发**：网关在流式管道中禁止对整个 Response Body 进行内存重组与缓冲等待，必须采用流式 Chunk 管道（Stream Pipe）直通，仅在旁路对 Chunk 进行增量状态统计。
3. **Usage 补全机制**：
   - 若上游支持 `stream_options: {"include_usage": true}`，网关在透传最后一个 Data Chunk 前确保带有 `usage` 字段。
   - 若上游不支持（如部分旧版接口），网关内置流式累加计数器，在触发 `[DONE]` 之前由网关主动构造包含完整 `usage` 的合成 Chunk 发给客户端，确保统计一致性。
4. **异常断开处理机制**：
   - **下游客户端主动取消**：网关监听客户端 `client disconnected` 事件，立即向对应上游通道发送 HTTP `Cancel/Abort` 信号，立即终止上游计费与推理算力消耗。
   - **上游连接中途异常中断**：若网关已向客户端发送过第一帧数据（首字），此时无法透明 Fallback 到另一厂商，网关必须向 SSE 流推送标准化 Error Event，并规范关闭连接，记录异常日志：
     ```json
     data: {"error": {"message": "Upstream connection reset during generation", "type": "upstream_error", "code": 502}}
     ```

### 4.4 错误码透传与标准化映射矩阵
网关必须屏蔽上游五花八门的厂商错误格式，统一转译为标准 OpenAI 错误结构体：

```json
{
  "error": {
    "message": "详细错误原因描述",
    "type": "invalid_request_error | authentication_error | rate_limit_error | server_error | gateway_error",
    "param": null,
    "code": "context_length_exceeded | invalid_api_key | quota_exceeded | upstream_timeout"
  }
}
```

| HTTP 状态码 | 错误分类 (Type) | 错误代码 (Code) | 触发场景判定 | 网关处理逻辑 |
| :---: | :--- | :--- | :--- | :--- |
| **400** | `invalid_request_error` | `invalid_request` | 客户端参数缺失、格式错误、模型不存在 | 直接拦截返回，不请求上游，不扣除配额。 |
| **400** | `invalid_request_error` | `context_length_exceeded` | 上下文 Tokens 超过所选模型上下文上限 | 上游报错后原样转换返回，给出建议使用的长文本模型。 |
| **401** | `authentication_error` | `invalid_api_key` | 客户端提供的 `sk-corp-*` 错误、已吊销或不存在 | 网关鉴权层直接阻断，记录安全审计日志。 |
| **403** | `permission_denied` | `model_not_allowed` | 用户所属组织/Key 权限无权访问指定受限模型 | 网关权限层拦截，提示联系管理员开通权限。 |
| **429** | `rate_limit_error` | `rate_limit_exceeded` | 客户端触发个人/应用级 QPS 或 TPM 上限 | 返回 429，并在 Header 携带 `Retry-After: 3`。 |
| **429** | `rate_limit_error` | `quota_exceeded` | 部门或个人账户月度配额已耗尽 | 返回 429，提示当前额度已用罄。 |
| **429** | `upstream_error` | `upstream_rate_limit` | 上游特定渠道出现 429 限流 | **触发内部自动 Failover**，切换至下一备用渠道；若所有渠道均 429 则返回该错误。 |
| **502** | `server_error` | `upstream_connection_failed` | 上游厂商服务崩溃、Cloudflare 拦截、DNS 失败 | **触发内部自动 Failover**，重试次数用尽后向客户端暴露该错误。 |
| **504** | `server_error` | `gateway_timeout` | 上游处理耗时超过设定的 Timeout（如首字 30s） | **触发内部自动 Failover**（若未吐首字），重试耗尽返回超时错误。 |

### 5.1 首批上游供应商接入范围

| 供应商名称 | 接入类别 | 接入协议 | 认证方式 | 纳管模型范围示例 |

| **Anthropic** | 海外公网云服务 | Claude Messages API | x-api-key / AWS Bedrock Token | `claude-3-5-sonnet-20241022`, `claude-3-5-haiku-20241022` |
| **DeepSeek** | 国内公网云服务 | OpenAI 兼容接口 | Bearer Key (支持多账号池) | `deepseek-chat` (V3), `deepseek-reasoner` (R1) |

### 5.2 渠道连接池与 Key 池管理（Provider Channel Pool）
针对任一上游供应商，网关支持配置多个独立渠道（Channel）：
1. **多 Key 轮询机制**：每个渠道支持绑定多个上游 Master API Key，网关层自动以轮询或最小活跃请求数调度，有效分散上游单 Key 的并发频次限制。
2. **渠道参数配置项**：
   - `channel_id`（唯一标识）
   - `provider`（openai / anthropic / deepseek / dashscope / custom）
   - `base_url`（支持自定义中转端点或内网地址）
   - `api_keys`（Master Key 数组，密文存储）
   - `weight`（权重，整数 1~100）
   - `priority`（优先级，整数 1~10，数值越小优先级越高，用于主备）
   - `timeout_ms`（请求超时，默认 60000ms）
   - `concurrency_limit`（单渠道最大并发数限制）

### 5.3 模型目录与高级别名映射机制（Model Aliasing）
网关对外屏蔽各厂商复杂的底层模型名称，提供三层别名解析：

```
客户端请求模型名
       │
       ▼
 1. 统一标准别名解析（例如请求 "gpt-4o"）
       │
       ▼
 2. 路由策略匹配（根据权重/健康度选取可用渠道）
       │
       ▼
 3. 映射至上游真实模型标识（如映射到 Azure "my-gpt-4o-deployment" 或 官方 "gpt-4o-2024-08-06"）
```

- **泛型智能别名（Smart Router Aliases）**：
  - `auto`: 自动根据 Prompt 长度与任务复杂度路由到最具性价比的模型。
  - `smart-fast`: 自动路由至低延迟高性价比模型（如 `gpt-4o-mini` 或 `deepseek-chat`）。
  - `smart-coding`: 自动路由至最强代码模型（如 `claude-3-5-sonnet` 或 `qwen2.5-coder-32b`）。
  - `smart-reasoning`: 自动路由至强推理思维链模型（如 `deepseek-reasoner` 或 `o1`）。

### 5.4 故障容灾与断路器机制（Circuit Breaker & Fallback）
为满足高可用性，网关执行以下容灾状态机逻辑：
1. **状态定义**：
   - `CLOSED`（健康）：正常转发请求。
   - `OPEN`（熔断）：渠道暂停接受新请求，所有流量切换至 Fallback 通道。
   - `HALF-OPEN`（半开试探）：在熔断冷却期（如 30 秒）过后，允许 1% 流量进行试探探测。
2. **熔断触发规则**：
   - 滑动窗口内（统计过去 20 次请求），连续出现 3 次超时或上游返回 `5xx` / `429` 响应，或错误率超过 25%，断路器立即转为 `OPEN`。
3. **降级回退执行链条（Fallback Chain）**：
   - 管理员可针对每个模型配置回退链，例如：
     `gpt-4o (主: 官方通道 Priority 1)` -> `gpt-4o (备: Azure 通道 Priority 2)` -> `claude-3-5-sonnet (跨厂商降级 Priority 3)`。
   - 在客户端未接收第一帧前，发生上游错误直接执行重试下一跳，最大跳数限制为 3 次。

## 6. 用户体系、KEY 分发与配额/计量模型

### 6.1 组织架构与用户生命周期

```
公司根租户 (Tenant)
  └── 部门 (Department，如：技术中心)
        └── 项目组 (Project Team，如：移动端团队)
              └── 用户 (User，如：张三)
                    └── API Keys (如：Cursor-Key, Test-Key)
```

1. **用户注册与身份同步**：
   - 默认禁止公网无感注册，仅支持企业 SSO（飞书/企业微信/钉钉/LDAP）自动关联生成账号。
   - 首次登录自动创建个人基础账号，加入默认未分组组织。
2. **员工离职与状态冻结**：
   - 对接 SSO 离职回调 Webhook 或每日定时目录同步；员工离职时，自动冻结其账号并吊销名下所有 API Key。

### 6.2 内部 API Key 规范与生命周期管理
1. **Key 编码格式与熵值**：
   - 统一格式：`sk-corp-<32位由大小写字母与数字组成的随机高熵字符串>`。
   - 示例：`sk-corp-Ab7Xk9Pq2LmN5RtY8Wz0VbC1DxEf3Gh4`。
2. **安全存储机制**：
   - 数据库**严禁明文存储 API Key**。
   - 数据库仅保存 `key_hash`（采用 `SHA-256(salt + key)`）以及展示掩码（如 `sk-corp-Ab7X...Gh4`）。
   - 生成时通过前端弹窗提示用户仅可复制一次，后续不可找回明文，仅支持重新生成或吊销。
3. **Key 属性绑定**：
   - 绑定的拥有者（User ID）、所属项目组（Project ID）。
   - 独立限额：该 Key 独立的单月/总用量上限（Dollar 或 Tokens）。
   - 速率限制：自定义绑定专属 QPS（如 20 req/s）与 TPM（如 500k tokens/min）。
   - 模型白名单：限制此 Key 仅可访问指定模型（如仅允许访问开源模型，禁止调用昂贵模型）。
   - IP CIDR 白名单：限制仅限开发机或特定服务器内网 IP 访问。
   - 失效时间：支持设置永久有效或指定到期时间。

### 6.3 配额控制与限流算法（Hard/Soft Quota & Rate Limit）

```
                  收到用户请求
                       │
                       ▼
            【第 1 关：API Key 鉴权】
              (有效性、未过期、未冻结)
                       │
                       ▼
           【第 2 关：并发与频次限流】
        (Token Bucket 算法：验证 QPS/TPM)
                       │
                       ▼
            【第 3 关：账户额度校验】
     (原子性校验：User Balance > 预估最小额度)
                       │
                       ▼
                 通过，转发上游
```

1. **多层级配额扣减逻辑**：
   - **预扣与结算两阶段**：
     - *请求前*：网关根据输入 Tokens 粗估最小预扣值（例如 200 Tokens 对应金额），若余额不足则直接返回 `429 Insufficient Balance`，避免上游空跑。
     - *请求完成*：从流式终帧或非流式响应中获取精确 `prompt_tokens` 与 `completion_tokens`，按平台统一定价字典计算实际费用，在 Redis 执行原子差额结算（Lua 脚本）。
2. **配额类型**：
   - **软限额（Soft Limit）**：消耗达 85% 时，触发邮件/飞书 Webhook 告警，但请求不阻断。
   - **硬限额（Hard Limit）**：消耗达 100% 时，立即阻断后续请求，返回 `429` 错误码。
3. **超高并发限流算法标准**：
   - 采用 **Redis + 本地内存二级滑动窗口令牌桶算法**。
   - 网关本地保留 1 秒内短频令牌缓存，减少 Redis 集中读写压力；超量突发流量按平滑漏桶排队或直接丢弃。

### 6.4 计费核算模型与 Token 统计口径
1. **定价体系**：
   - 支持多币种汇率统一折算（上游 USD/RMB 统一换算为公司内部积分点数或标准人民币元）。
   - 可配置加价系数（Markup Ratio，例如内网按成本价 1:1 核算，或针对外部合作方设定 1.2 倍系数）。
2. **统计口径优先级**：
   - **第一优先级（权威口径）**：读取上游 API 响应中附带的 `usage.prompt_tokens`、`usage.completion_tokens` 与 `usage.total_tokens`。
   - **第二优先级（兜底分词）**：若上游因异常中断或流式协议缺失未能提供 Usage，网关后置处理调用内置标准分词器（OpenAI Tiktoken `cl100k_base` / `o200k_base`，Claude Tokenizer）计算出精确 Token 数入库，杜绝 0 Token 漏计。

## 8. 边界条件、异常处理与高可用容灾

### 8.1 网络抖动与上游异常保护机制
1. **动态重试机制（Idempotent Retry）**：
   - 仅对上游未写入第一字节前出现的网络连接拒绝（ECONNREFUSED）、TCP 连接超时、DNS 无法解析或 `HTTP 502/503/504` 进行自动切换渠道重试。
   - 最大重试次数锁定为 3 次，超过直接判定单次请求失败。
   - 严禁对非幂等已生成部分内容的流式连接进行二次盲目重发。
2. **长连接保持与连接池优化**：
   - 网关与上游供应商之间强制采用 HTTP/1.1 或 HTTP/2 长连接保持（Keep-Alive Pool），预热空闲连接数，避免高并发下反复 TCP 握手与 TLS 协商造成的额外延迟。

### 8.2 极端并发下的降级与背压控制（Backpressure）
1. **系统高载自我保护**：
   - 网关设置全局最大处理并发上限（如单节点最大并发 5,000 活动连接）。
   - 当系统 CPU 占用率持续 > 85% 或待处理排队请求数超过队列深度上限时，网关立即触发自我保护背压机制，边缘层直接返回 `503 Service Temporarily Unavailable`，优先保证在途流式会话不中断。
2. **内存溢出（OOM）防护**：
   - 严禁任何组件在内存中无限制全量缓存大型文档请求或超长输出。
   - 单请求最大 Body 尺寸硬限制：默认最大接收 32MB（满足长上下文/多模态图片传参），超出限制直接在边缘层返回 `413 Payload Too Large`。

### 8.3 数据合规与审计脱敏规则
1. **Prompt 数据隐私保护**：
   - 网关默认**仅落盘元数据（Metadata）**：包括 RequestID、时间戳、UserID、KeyID、Model、耗时、Tokens 数量、HTTP 状态码。
   - 对请求的具体 Prompt 内容和 LLM 生成内容，默认不持久化存储于关系型数据库，避免企业商业机密或员工隐私泄露。
   - 若合规安全审查强制要求审计，仅在独立加密日志中心以 AES-256 存储经过脱敏处理的密文，且需双人授权（合规员 + 超级管理员）方可调阅。

## 10. “复刻 OpenRouter”功能边界冻结清单

为确保第一期（v1）研发资源高度集中于**公司内部核心高并发转发与稳定性**，防止范围蔓延，对 OpenRouter 公网商业化功能进行严格的边界冻结：

```
┌─────────────────────────────────────────────────────────────┐
│                    本期建设范围 (IN-SCOPE)                   │
├─────────────────────────────────────────────────────────────┤
│ 1. 统一 OpenAI 协议网关 (/v1/chat/completions, /v1/models)   │
│ 2. 多供应商协议适配 (OpenAI, Claude, DeepSeek, 百炼, 私有化) │
│ 3. 跨渠道负载均衡、故障自动 Fallback、断路器机制            │
│ 4. 内部 API Key 签发、多级配额预算、高并发令牌桶限流        │
│ 5. 企业 SSO 单点登录对接与组织/部门权限管理                 │
│ 6. 管理员运维监控大盘与开发者自助控制台                      │
│ 7. 审计日志、用量统计与部门费用分摊报表导出                  │
└─────────────────────────────────────────────────────────────┘
                               ▲
                               │ 严格隔离边界
                               ▼
┌─────────────────────────────────────────────────────────────┐
│                    明确延后范围 (OUT-OF-SCOPE)              │
├─────────────────────────────────────────────────────────────┤
│ 1. 外部公网用户注册与公开计费结算 (Stripe, 信用卡, 微信支付) │
```
